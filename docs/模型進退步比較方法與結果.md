# 模型進退步比較方法與結果

比較時間（Asia/Taipei）：2026-10-14T00:54:10+08:00。這次只推論與驗證，沒有另做訓練。

## 怎麼判斷進步或退步

**把線上舊版與候選新版放在相同測試上，不拿不同資料或訓練 loss 直接比較。** 固定輸入、資料目錄、推論流程及評分方法後，計算「新版 − 舊版」；正確率／NDCG 越高越好。整體平均沒有降低也不夠，還逐案例找「舊版會、新版不會」的退步，重要品牌排除、解除、預算與澄清有退步就不切換。測試不足則寫不能判定，不當成通過。

公開 JSON 在 [模型進退步比較結果](模型進退步比較結果.json)，包含各案例、預期條件、模型版本／checksum、分數與結果。這些例句是助理另行編寫的合成案例，不是真實用戶對話；沒有原始帳號、cookie、金鑰或互動資料。

## Qwen：比較真正網站流程中的意圖理解

舊版是網站原本的 Qwen3-8B 4-bit intent-v3；候選是 `20261013T232109-qwen-intent-qlora` 的 adapter。兩版使用同一基礎 revision、同一 SYSTEM、相同非思考模式及 greedy generation（temperature=0、最多 320 tokens）。

這次 **另寫 12 個網站情境**，沒有用它們訓練或挑 adapter。由真正的 `conversationTurn` 先合併本輪條件，`catalogFeatures` 提供目錄欄位，連同相同品牌／茶種／配料列表給兩個模型；再模擬 Qwen.parse 未知配料 guard 的強制澄清，最後送入真正 `applyLlmUnderstanding` 合併。

先看模型原始 JSON 的 action／完整 filters，再看整個網站流程的 action／完整 filters。空排除陣列與未填排除視為同義，陣列順序不影響；其他數值、布林、品牌等必須一致。assistantMessage 文案及 query 自由文字不要求字串一樣，因此這張表是 action／條件正確率，**不是所有 JSON 欄位的完整語意準確率**。下游條件有些由網站規則修正，不能把它的成功全部算成模型學習成果。

先前訓練報告的 60%→80% 用的是另外 10 個合成情境，而且採嚴格 action/query/filters 全一致；這次網站測試有實際預先合併的 state，且不要求自由 query 字串相同。因此兩種數字不能直接相減或說互相矛盾。模型可以在一份小測試改善，同時在另一份情境退步。

## MacBERT：比較同一飲料目錄的查詢排序

舊版模型為 `macbert-5754da458c249ff9`，候選為 `macbert-8e08de527639956d`。兩版固定使用目前同一份 5,781 杯型、2,603 品項目錄、相同 mean pooling／L2 normalization、max length=64 與 cosine 分數，分別建立各自目錄向量。按品牌＋品名合併杯型，以最佳杯型分數代表品項，不讓同一飲料的多個杯型占滿前十名。

12 個固定查詢的相關標籤，直接依目錄已有的品牌、茶種、奶類與配料欄位定義；沒有讓模型自己判定答案。例如「紅茶加鮮奶」的相關品項必須有紅茶、鮮奶且沒有奶類矛盾。這是**欄位標籤的相關性代理測試**，不是消費者口味評分、人工盲測或整體網站滿意度。為檢查向量检索本身，先在整份目錄排序；網站仍會另做硬條件篩選。

Precision@10 = 前十名有多少符合標籤 ÷ 10。NDCG@10 = 符合標籤的品項越靠前分數越高，再除以理想排序；範圍 0–1。也記錄 Recall@10，但相關品項很多時，前十名最多只能找回少量，因此不把它單獨當發布門檻。

## RelGT：先檢查是否真的有獨立未來資料

舊版訓練 7 個目標、1 位用戶；候選訓練 10 個目標、2 位用戶，多了 3 個目標。本次重新匯出雲端仍為 10 筆事件、2 位用戶，沒有新增獨立目標。

這 3 個新增目標已被候選拿去訓練，不能再當候選的獨立測驗。若拿它們比較，對候選不公平地有利，可能只是背答案。當前候選訓練外的獨立時間驗證目標是 **0**，因此沒有可比較的獨立 Recall/NDCG，不能填進步／退步百分比。**RelGT 不切換。** 未來有新互動時，須先保留作舊新版共同時間驗證，避免先把所有事件拿去訓練再測同一批。
