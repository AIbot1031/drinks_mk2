# 3.0 中文語意檢索候選方案

使用者要求先實作與測試效率、推薦成果，結果交由使用者決定是否上線為 3.0。本次僅離線推論，不訓練、不部署、不改排程或服務。

## 實作

新增 `scripts/benchmark_encoders.py`，比較官方 `hfl/chinese-macbert-base`、官方 `hfl/chinese-roberta-wwm-ext` 及安裝中 MacBERT LaunchAgent 指定的微調 checkpoint。官方模型固定下載 revision，報告保留來源、權重 SHA256、目錄及查詢版本。不是因執行於 Mac 而選用 MacBERT。

三者沿用現有 Ranker.embed：64 token 截斷、排除 CLS/SEP/padding 的平均池化、L2 正規化、float32、eager attention、MPS、4 個 CPU 執行緒。飲料文字與現有服務一致；重新建立完整目錄向量，不使用既有索引快取。各模型用新子程序隔離，排除下載時間並暖機後測索引與查詢。此方案先替換語意編碼器作離線挑戰；正式系統的 Qwen、硬篩選、RRF、RelGT 不改。

## 成果評估

24 個人工撰寫的合成查詢，依真實目錄欄位建立二元相關標籤，不包含真實使用者對話。全部 5,781 杯型合併為 2,603 個品牌＋品名，每個品項取最高杯型相似度，與網站分組原則一致。比較 Precision@10、Recall@10、NDCG@10，保留每則查詢的前 10 名、逐查詢改善／退步數量。

本次不先把查詢的茶種／配料／品牌條件拿來硬篩選，以免答案預先被篩出而掩蓋編碼器差異。因此這是路徑 A 的獨立診斷，不是完整網站品質評估。標籤用來檢查可核對的茶種／奶類／配料相關性，不能判斷「清爽回甘」等主觀口味。奶類標籤排除 milkConflict；每則查詢驗證都有正例與負例。奶茶＋配料查詢接受有茶種標籤或品名明示「奶茶」的含奶品項，避免缺茶種欄位造成明顯假陰性。其他目錄缺漏仍可能影響分數，不把欄位標籤當成完整人工真值。

## 效率評估

記錄本機載入秒數、暖機後首次完整索引秒數及杯型吞吐量。各查詢完整單次編碼＋全目錄相似度＋品項分組排序，依相同查詢順序重複 3 次，共 72 次，回報中位數與 P95。本機查詢不含網路、Worker 或完整網站 RRF。另記錄程序峰值 RSS、MPS active／driver 記憶體與模型權重大小；統一記憶體可能重疊，不相加。載入時間受 OS 快取影響；現有服務仍運作，沒有停止它們。

## 決策與限制

本次完全沒有 optimizer 更新或新訓練權重。原始模型間比較可用來初步判斷起始編碼器；原始 RoBERTa 對現有微調 MacBERT 是替換可行性比較，不能把差異全歸因於模型架構。MacBERT 微調曾見過目錄文字，本次目錄不屬於未見過的測試集。查詢的改寫彼此相關，單次小樣本平均分數不能證明統計優勢。

上線前需固定未用於調參的人工查詢—飲料相關性測試，再比較兩者相同資料／步數微調後的結果，並驗證硬篩選、離線備援與版本回復。本次若結果只是各有勝負，維持現有模型；只有使用者看過結果明確決定，才另做 3.0 發布。
