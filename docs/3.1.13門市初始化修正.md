# 3.1.13 門市初始化修正

3.1.12 已部署門市供應第一階段，正式 D1 遷移及 API 驗證通過；隨後正式瀏覽器驗證發現，帳號初始化尚未完成時快速選門市，畫面選項可能改了但內部門市未套用。當時正式頁面顯示「未選門市」，沒有誤宣稱門市供應已確認，但推薦可能仍跨品牌。

3.1.13 在門市控制器建立時依帳號／請求狀態鎖住選單與表單，並由同一個互動狀態刷新函式統一解鎖。被阻擋的變更會把畫面選項恢復至實際選擇，避免出現假選擇。保留 3.1.12 的門市供應、缺品回報及原條件替代推薦；沒有新增資料表、模型訓練或付費服務。

新增回歸測試涵蓋初始化鎖定、就緒後選擇成功、忙碌中變更不會清掉已選門市，也不會留下不同於內部狀態的畫面選項。本機 Worker 全套 140 項，134 通過、6 略過、0 失敗；略過項目需要模型金鑰或額外監督台測試環境。TypeScript 與部署 dry-run 通過。

門市資料目前僅兩筆公開來源，未收錄者可手動輸入；供應預設待確認，不是即時庫存，仍需人工查證與補充。完整功能與限制見 [第一階段設計](3.1.12門市供應與缺品回報.md)。

2026-10-20 正式 Worker 0c5dd7ef-fd4c-4015-9f10-ff3881765112 已部署；健康檢查與六個資產雜湊確認 3.1.13，既有 Cron 不變。正式瀏覽器確認載入時選單 disabled，載入完成後門市套用成功；六張結果均為 CoCo都可，70 元／綠茶條件保留，顯示供應待確認及兩種缺品按鈕。未對真實門市提交測試缺品。正式 API 的兩種隔離回報、同店原條件替代、其他分頁與其他門市隔離、零元無結果、匿名資料不公開及回報關閉均通過。
