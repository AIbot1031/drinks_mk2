# 近乎零咖啡因與當輪條件修正

2026-10-14，Asia/Taipei。使用者提供四張截圖，並以文字確認原句「100元內 茶類 咖啡因含量近乎為零」。其餘可見寫法為「咖啡因含量為零」「咖啡因為零」「咖啡因=0」。這次直接使用這些文字構造訪客請求，不再以其他數值例句代替原句。

## 圖片顯示的問題與可以確認的事

圖片有口味中殘留咖啡因描述、上方咖啡因 ≤ 0 mg 與熟成紅茶卡片並存的情形。這個畫面不能作為零咖啡因已正確生效的證據。先前只用 50 mg 等例句的測試不足以涵蓋這四種寫法。

目前目錄中可不可熟成茶行「熟成紅茶」中杯的咖啡因顯示文字為 200，大杯為 201，數值上界欄位為未知；風味描述另有中杯 101–200 mg、大杯 ≥201 mg。它不符合目前「資料已知、非估算、上界為 0」的篩選條件。本次沒有修改或推測目錄數值，也沒有重建模型索引。

修改前的最近正式版實測中，「含量為零」「為零」已能使用 0 mg 並排除熟成紅茶；「近乎為零」只有一般數值追問，「=0」仍被當成待釐清，未直接套用。本次沒有重現最近正式版在 0 mg 生效時回傳該紅茶，不能編造圖片當時的 API filters 或根因。

另外，原介面在對話頂端顯示最新全局條件，歷史回答沒有自己的條件紀錄；因此單靠頂端標籤無法判斷下方某一則歷史回答當時使用的篩選。這是程式可確認的呈現缺口，本次補上每輪條件。

## 現在的處理

| 原句／寫法 | 行為 |
| --- | --- |
| 100元內 茶類 咖啡因含量近乎為零 | 口味保留茶類，預算≤100元；針對近乎零追問是嚴格0mg，或明確指定可接受上限；暫不推薦 |
| 咖啡因含量為零 | 咖啡因≤0mg，保留口味及預算 |
| 咖啡因為零 | 同上 |
| 咖啡因=0 | 同上；亦支援全形等號／數字及「等於零」 |

「近乎零」沒有唯一的數值定義，所以不自行指定為 5、50 或 100 mg。提供「嚴格 0 mg」按鈕，或讓使用者自行輸入上限。咖啡因語句不放入口味。新的 pending 原因是 `approximate-zero`，不讓 Qwen 臆造容許量。

API 回傳的對話狀態使用推薦引擎實際篩選條件；回覆前另核對「已驗證的輸入條件＝結果條件」，並核對每個可選杯型是否符合硬篩選。若發現不一致，停止顯示並回傳503，保留錯誤事件；不能只留下看似已套用的0mg標籤。

每則新回答附有「這次推薦使用的條件」或「本輪保留的條件（待確認）」。沒有咖啡因上限時寫明未設定；待確認時顯示待確認，避免把先前保留的0mg當成本輪已確認值。歷史回答的條件標籤不隨後續修改。上方條件列仍代表目前對話。
