# 使用者流程檢查與修正

核對時間：2026-10-13T21:59:25+08:00（Asia/Taipei）。以網站實際 UI、線上 API 與獨立本機 Worker 測試核對。使用自製測試語句與訪客偏好，不登入或修改真實用戶帳號，不將測試收藏當成真實訓練資料。

## 發現與修正

| 問題 | 修正後行為 |
| --- | --- |
| 珍珠可以了仍保留珍珠排除 | 明確取消該排除，其他預算／品牌條件保留，不自動要求加珍珠。 |
| 春水堂可以了仍保留品牌排除 | 只取消該品牌排除，不指定品牌。 |
| 改喝純紅茶被追問配料 | 轉為紅茶、無奶、milkTea=false，保留未修改限制並正常推薦。 |
| Qwen 回覆說不加珍珠，但實際卡片有珍珠 | 確認文字由驗證後的有效條件生成；追問仍可使用受限 Qwen 問句。 |
| 模型可能亂加品牌／配料排除或預算上限 | 新排除須有本輪明確文字依據；數值上限只依明確數值更新，保留已解析條件。 |
| 不喜歡珍珠同時變成要求與排除珍珠 | 共用語句正規化加入配料否定；合併後清除與排除相衝突的要求。 |
| 紅茶拿鐵僅依排序碰巧命中鮮奶 | 茶拿鐵／歐蕾轉成茶種與鮮奶條件，鮮奶候選排除奶精混合標記與奶類矛盾。 |
| 鮮奶茶不要奶精被判無奶 | 搭配明確鮮奶／植物奶選擇時正確處理奶精否定；不把奶精字首當成不喝全部奶類。單獨排除奶精不是此輪新增完整奶類排除介面。 |
| 換批重新跑 Qwen，可能改動條件且較慢 | 再推薦幾杯使用 quick-command，保留 query／filters，只排除已看品項，仍使用 A／B 排序。 |

Qwen 推論程式／提示契約改為 intent-v3；沒有微調模型權重、沒有執行訓練。

## 仍可優化與限制

這些是少量自製案例，不能當成全面語意準確率。接下來最有價值的是固定更多否定／改口／多輪案例，加入人工查詢—飲料相關性評估，分開測需求理解與排序品質。較複雜口語仍可能無法解析；奶類／營養來源缺值與估算限制仍存在。

Qwen 一般對話仍較慢，後續可量測輸入上下文、排隊與生成時間，再決定提示縮減或快取，不先猜模型規格或品質提升。這次只略過沒有新語意的換批指令。

RelGT 仍為 1 個訓練帳號、7 筆事件模型，沒有獨立驗證集；本輪沒有重訓、沒有變更權重、沒有啟用排程。未使用真實手機驗證 LAN／響應式畫面，本輪 UI 為桌面瀏覽器。未提交或推送 Git。
