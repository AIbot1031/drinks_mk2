# Qwen 奇怪輸入微調設計

使用者於 2026-10-14 要求針對人類奇怪輸入，實際微調目前的 Qwen。這次使用既有 Qwen3.5-9B MLX 4-bit 固定快照與 intent-v7 提示，採 QLoRA；MacBERT、RelGT、前後端正式服務與排程不因本次訓練自動切換。

## 合成情境

來源為助理人工編寫的 `training/qwen_robust_cases.py`，不是實際顧客資料，也不是讓待訓練模型替自己產生標籤。

| 類別 | 例子或目標 |
| --- | --- |
| 錯字、注音、中英混寫與重複符號 | 奶查、ㄋㄞˇ茶、milk tea、black tea、連續驚嘆號 |
| 否定、雙重否定與配料矛盾 | 珍奶不要珍、不是不要奶茶、只排除配料 |
| 解除與重新指定 | 珍珠可以不等於一定加珍珠；取消品牌排除不等於指定品牌 |
| 數值與單位 | 全形數字、中文數字、零、小於／以下、公克換毫克 |
| 無效或不明範圍 | 負數、每毫升、上下限區間；先追問而不是亂取值 |
| 心情夾雜口味 | 開心、疲累、孤單、壓力與口味同句，不臆造篩選 |
| 指令混淆 | 忽略規則、偽 system／JSON／標籤、要求讀密碼或移除限制 |
| 無明確意圖與離題 | Emoji、你猜、含糊回答、請寫程式 |
| 過敏或醫療保證 | 不保證成分或治療效果；要求補充可驗證飲料需求 |
| 跨輪改口 | 保留未修改條件、只改一欄、換批、重新開始 |

73 筆訓練、30 筆另行編寫的組合驗證、29 筆既有網站回歸案例；共 59 筆固定驗證。現有回歸情境只用來評估，沒有加入訓練目標。驗證和訓練共用任務詞彙，但實際送入模型的完整 payload 無重複；「重新開始」之類共用語句要在 Worker 預處理後檢查，避免前置狀態清除後變成同一筆輸入。

`scripts/build_qwen_robust_cases.ts` 使用目前 `conversationTurn` 處理前置狀態，生成包含實際品牌、茶種、配料與 catalogFeatures 的 `training/qwen_robust_snapshot.json`。人工語意標籤與規則輸出各自保留。訓練資料在正式規則會略過 Qwen 的情境，也會做獨立模型探測；不把這些模型探測都說成正式網站請求。

## 訓練及驗證

- 初次規劃最後 4 層 rank 8 adapter；實際在第一步反向運算遇到 Metal 記憶體不足，0 個完成的 optimizer updates。失敗報告保留。
- 記憶體修正後改為最後 1 個完整注意力區塊、rank 8 adapter；batch 1、目標 146 optimizer steps、learning rate 0.00005、seed 42。凍結的 DeltaNet 區塊採推論 kernel，只有 adapter 所在區塊採訓練模式，不改基礎權重。
- `training/qwen_completion_loss.py` 保留整段輸入，僅對最後 512 個位置建立詞彙 logits；預檢每筆回答加 padding 都在視窗內，遮罩仍只計算回答 token。實機第一筆 loss 與原 masked CE 誤差 0.0，兩者皆計 62 個回答 token；沒有截斷或移除任何硬條件。
- Prompt loss 遮蔽，只學 JSON 回答；序列上限 3072，預檢最長 2190 tokens，超長直接失敗，不截掉目標。
- 保持正式 SYSTEM、未知配料 guard 的附加提示、非思考模式、greedy／temperature 0、max generation 320 一致。前後使用同一份固定驗證，不依結果更換題目。
- 指標分開記 JSON／schema 合法率、action＋filters 完整一致率、query 一致率與整體意圖一致率。query 僅允許人工列出的同義字串及標點／空白正規化，不用另一個模型任意判對。
- `scripts/score_qwen_robust.ts` 對相同生成結果重播目前服務的數值 null codec、未知配料覆寫與 Worker 合併程式。這是本機合併探測，沒有冒充完整正式 HTTP／硬篩選／排序評估；另列原本會略過模型的情境。
- 每 25 步保存 checkpoint，結束後確認 adapter 改變、基礎檔案不變、保存／重載 logits 一致；原始合成生成結果留在忽略 Git 的訓練目錄，安全報告留在 docs/training-runs。
- 重試只在資料、提示、生成設定、模型權重 hash 與全部 59 個案例一致時重用已完成的微調前生成；來源是先前失敗執行的訓練前評估，失敗時尚無完成 optimizer 更新。微調後仍重新生成全部 59 題，不以重播冒充新模型推論。
- 訓練期間的 token loss 只抽 8 個 validation batch，抽樣不保證前後相同，作診斷使用，不納入改善差值；真正前後比較採固定全部 59 題的生成語意指標。

## 限制與發布

資料是小型助理標註合成集，沒有獨立人工標註一致性或真實用戶分布保證。明確的規則錯誤可能先把條件放錯，模型即使理解原句，現有合併規則仍可能不允許修正；不能把所有下游錯誤都歸因 Qwen，或把原始模型分數當成推薦滿意度。

例：雙重否定可能誤留無奶限制、每 100 毫升含量可能被當成每杯、配料後置「不要」可能被當成正向配料。另有英語／注音別名能被模型理解，但 Worker 的明確文字核對可能阻擋。這些保留在獨立驗證與限制中，本次不偷偷修改正式規則迎合分數。

本次先保存微調候選，不自動替換正式 adapter。實際步數、前後指標、重載結果及發布決定以每次訓練報告為準；任何失敗或退步也必須保留，不以 loss 降低冒充語意改善。

方法參考：[MLX-LM 官方 LoRA／QLoRA 說明](https://github.com/ml-explore/mlx-lm/blob/main/mlx_lm/LORA.md)。
