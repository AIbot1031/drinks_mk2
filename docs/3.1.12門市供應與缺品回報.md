# 3.1.12 門市供應與缺品回報（第一階段）

## 規劃與範圍

沿用現有 Cloudflare Worker、D1、瀏覽器分頁儲存與排名提示，不新增付費地圖、定位、爬蟲服務、AI 服務或訓練。門市供應與個人口味分離，缺品不會建立收藏／不喜歡事件。此階段不是即時庫存，也不宣稱已收錄全台門市或各店完整菜單。

初始清單僅收錄 CoCo 都可新竹中正店與新竹清大店的公開門市名稱及地址，來源為 [2026 新竹市購物節門市清單](https://shopping.hccg.gov.tw/brands/coco)，核對日期 2026-10-20。此來源僅支持門市資料，不支持任何飲料在該店一定有售；正式初始品項供應狀態全部待確認。虎尾 CoCo 原回饋未指明完整門市，也未查證，不預先標記其 3Q 奶茶未販售。

未收錄門市可填品牌、店名及完整營業地址。以正規化後的品牌／店名／地址產生識別碼，不依使用者提供的 id 或 verified 判定。只有回報時才保存該手動門市，未查證前不公開加入清單；後台可在核對公開來源後收錄。無定位權限要求，不保存使用者位置軌跡、IP、帳號 ID 或個人聯絡資料。

## 實作

- 新增 `0007_store_availability.sql`：門市、品項供應及待查證回報三張表。所有寫入使用 D1 綁定與參數化 SQL；查證供應及回報狀態以同一 batch 保存。
- 新增門市搜尋／選擇與手動門市表單，選擇在同一分頁保存，與帳號口味偏好分開。
- 推薦卡片標示供應待確認或已查證供應、最後確認日期、查證依據及公開來源。已查證未販售／售完的品項在模型候選及結果前排除，已確認供應優先於未知品項，但不能越過原有硬篩選。
- 「今天售完」「菜單沒有」分開回報。每筆以品牌＋品名為單位，影響該門市此飲料全部杯型。保存成功後先在回報者分頁排除，重用原排名提示刷新手動／最新對話推薦；保留預算、營養、奶類、茶種、配料、品牌及既有品項排除，不重訓或再次呼叫模型。
- 指定門市時不列放寬原條件的接近選擇。沒有同店且完全符合的替代品項就如實顯示無結果；不換品牌、不提高預算。門市品牌與明確指定品牌衝突時給出說明。
- 歷史對話的回報按鈕停用，避免把舊條件的卡片當成最新推薦。重設手動條件會清除舊卡片。回報功能放在推薦卡片，圖鑑／收藏卡片僅顯示供應提示。
- 本次缺品紀錄可解除分頁排除，不等同撤回回報或推翻已查證供應。今天售完於台灣時間隔日失效，菜單沒有的分頁排除七天後失效，切換門市不沿用上一家的排除。
- 後台沿用團隊登入及同源檢查。人工可確認供應／售完／未販售，或不採納；需要填查證依據。公開收錄門市需明確勾選並提供公開 HTTPS 來源。未登入不能查閱／審核回報。
- 查證供應七天有效、未販售三十天有效、售完至台灣時間隔日；過期自動回到未知。這是第一階段維護期限，不是店家即時庫存同步。
- 匿名回報只存隨機分頁代碼的雜湊；回報 ID 支援重送去重。最近 24 小時每個分頁代碼最多 20 筆、全站最多 200 筆，以限制第一階段免費配額使用。此代碼可由瀏覽器替換，不能當作已驗證身份；所有公開供應變更仍須人工查證。

## 驗證

- TypeScript、前端語法、版本／建置一致性及 Wrangler dry-run 通過。
- 本機 Worker 全套 139 項：133 通過、6 略過、0 失敗；略過項目需要未提供的模型憑證或其他後台測試環境。Python 意圖資料 5 項通過，其他 39 項通過（含 7 略過），沒有啟動實際訓練。
- 新增門市識別正規化、防偽 metadata、兩門市隔離、跨杯型排除、台灣跨日／七日失效、查證期限、來源要求、未登入阻擋、同源、回報去重、寫入上限、已確認供應優先與硬篩選測試。
- 本機瀏覽器確認選門市、手動未收錄門市、未知供應顯示、手動／對話缺品自動替換、70 元／綠茶條件保持、收藏數未變；後台查證表單保存後，已確認供應優先顯示。
- 本機的供應查證使用明確標示的合成資料，僅在本機資料庫，未帶入正式資料庫。

## 限制與維護

免費架構仍消耗既有 Worker／D1 配額，並不代表無限流量免費。門市及菜單需要人工持續補充；未查證供應不得當作一定有賣。地址的書寫差異可能建立不同手動門市，後續可增加後台合併工具。現階段沒有門市完整菜單匯入、店家庫存連線或自動抓取功能。
