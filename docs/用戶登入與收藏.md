# 用戶登入與收藏

## 消費者操作

打開 [飲料推薦網站](https://drinks-mk2.rtx941031.workers.dev/)，按導覽列的「登入 / 註冊」。首次使用自行填入 ID 與密碼，按「建立帳號」；之後用同一組資料按「登入」。註冊成功會自動登入。沒有預設共用用戶密碼。

- ID 至少 3 個字元，只能使用英文字母或數字。
- 密碼至少 6 位，只能使用英文大小寫或數字。
- 兩者區分大小寫，最多 200 個字元，不能包含中文、空白或符號。
- 同一個 ID 只能註冊一次；表單與 API 皆驗證。

登入後，喜歡與不喜歡會保存到自己的帳號，其他裝置登入同一帳號即可讀取。推薦 API 會採用帳號裡的偏好。登出後會回到這個瀏覽器原先的訪客偏好，帳號偏好不會留給下一個訪客。

訪客也可使用推薦與本機收藏。登入不會自動合併訪客偏好；需要時到「我的收藏」按「把此瀏覽器偏好加入帳號」。同一杯若同時出現在喜歡與不喜歡，喜歡優先。每種偏好最多 200 款。

儲存失敗會恢復上一份已保存的偏好並顯示錯誤。跨裝置更新採用最近成功保存的完整偏好版本；已開啟的另一個頁面須重新整理取得更新。目前沒有 email 驗證、忘記密碼、修改密碼或自助刪除帳號功能，請妥善保存登入資料。

## 與團隊後台的區別

這是獨立的消費者帳號系統。用戶登入不會取得 `/internal` 的存取權；團隊檢查 cookie 也不能登入用戶帳號。團隊後台現有 ID 與密碼維持原設定，後台不提供用戶帳號／密碼查詢。

## 儲存與安全

Cloudflare D1 的 `consumer_users` 保存 ID、獨立隨機 salt、PBKDF2-SHA256 密碼雜湊（100,000 次）、建立時間與偏好。沒有保存明文密碼；密碼不寫入推薦 trace、前端儲存或 GitHub。

`consumer_sessions` 只保存隨機 session token 的 SHA-256 雜湊，登入 cookie 為 HttpOnly、Secure、SameSite=Strict，有效 7 天。登出會立即刪除對應 session，登入會替換目前 cookie 的舊 session。到期 session 在之後登入時清理。

登入與註冊共用每個 IP 每 15 分鐘 40 次的限制；D1 僅保存時段化 IP 雜湊及次數，不保存原始 IP，過期計數在後續登入／註冊請求清理。同一網路下的用戶共用該限制。跨來源帳號操作會拒絕。

新增帳號及偏好不等同已完成 RelGT 訓練事件資料設計。推薦 trace 仍沒有用戶帳號欄位；訓練標籤、同意流程與時間切分仍需另行規劃。

## 開發與部署

執行 `npm run db:local` 建立本機表，`npm run db:remote` 建立線上表，再使用既有部署流程。新增表由 `migrations/0002_consumer_accounts.sql` 管理，不覆蓋既有推薦紀錄。不需要增加用戶帳號的共用 secret。

API：`POST /api/account/register`、`POST /api/account/login`、`POST /api/account/logout`、`GET /api/account/me`、`GET/PUT /api/account/preferences`。註冊及登入接收 `{id,password}`；偏好更新接收 `{likedIds,dislikedIds}`，伺服器核對飲料 ID，再回傳原始飲料資料。

`tests/accounts.test.ts` 在設定 TEST_BASE_URL 時驗證註冊、格式、重複 ID、錯誤密碼、跨來源阻擋、收藏隔離、登出與重新登入。整合測試會建立以 testauth 開頭的測試帳號。
