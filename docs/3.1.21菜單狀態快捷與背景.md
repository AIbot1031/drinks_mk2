# 3.1.21 菜單、模型狀態、手動快捷與雙色芋圓

## 空結果與真正備援

硬條件、地區、排除與換批讓候選數變為 0 時，A／B 路徑皆標記 `not-run`、原因 `no_candidates`，不執行文字或圖排序。手動及對話介面共用狀態文字：「沒有符合候選，未執行模型排序。」團隊紀錄也顯示未執行，不再誤認為 TF-IDF 或神經模型曾排序。

模型橋接分開記錄 `model_not_ready`（未連線或尚未就緒）、`catalog_mismatch`（索引版本不符）、`model_busy`（同時工作達 8 筆），以及 `no_valid_response`（5 秒逾時、請求期間斷線或模型主動回報失敗）。不合法、外部候選、空分數、非有限分數或舊版本回應均拒絕，標記 `invalid_reply`。橋接本身拋錯仍有獨立原因。

在 localhost 使用模擬代理逐一注入未連線、未就緒、版本不符、外部候選、錯誤、斷線、真實 5 秒逾時與 9 個同時請求，驗證備援原因。另確認偏好刷新保留本輪備援排名、模型恢復後新推薦會重新呼叫 RoBERTa，以及空候選不宣稱執行模型。模擬測試不是實際模型成效；證據為 `model-validation/3.1.21TFIDF回退情境驗證.json`。

真正的斷線、服務忙碌、逾時或無效回應仍需保留免費備援，不移除驗證或冒稱模型成功。收藏刷新為立即更新而沿用本輪排名，若該輪使用備援，畫面會提示重新推薦可重試語意模型。新使用者／無歷史仍保留 RelGT 原回退策略。

## 既有門市菜單

本次只盤點現有 41 品牌中 23 個原先空菜單門市，沒有新增品牌或門市。發現目錄建置程式漏帶既有逐店菜單欄位，已修正並讓供應狀態讀取更新後目錄。

補回或補齊 6 店：50嵐虎尾中正、林森、光復店，一沐日虎尾中正店、白巷子虎尾中正店，以及拾汣茶屋雲林虎尾店。白巷子來源本次連線未成功，保留同日已核對菜單與來源，明確記錄限制，不稱即時供應。

拾汣虎尾門市由[官方頁](https://www.19teahouse.com/works/detail/Store20)直接連至[肚肚菜單](https://store.dudooeat.com/order/store/f35db32f48734b868b7662391529bae7)，核對店名、電話 05-632-7900、中正路 137 號，取得 79 款飲料並排除杯袋。補充列共 248 個官方菜單規格，目錄變為 9,180 筆、3,875 款品牌品名產品，仍為 41 品牌；原 5,781 筆與既有你訂列不變。

依使用者提供的 [SipSpot](https://sipspot.wisplu.com.tw/)只查缺資料的既有品牌，保存品牌參考菜單；其頁面明示價格以門市為準，沒有逐店販售證據，不能把它的全品牌菜單套到所有虎尾門市。因此其餘 17 店逐店供應仍待確認，沒有假裝全部補完。逐店嘗試、來源連線結果、參考品項及限制完整保存在 `data/research/branch-menu-audit.json`。

官方補充列保留待確認的完整售價、杯型、熱量、咖啡因、成分、配料與供應；不借用同品牌其他地區的營養或價格。有預算、營養、配料排除等硬條件時，未知列不能通過。地區投影只連向實際核對的門市來源。重複品名仍合併、不同來源及適用門市保留，收藏與不喜歡及取消即時共用。

新目錄使用同一 RoBERTa／RelGT 權重重建索引與推論表，未訓練、optimizer 步數 0。原 RoBERTa 向量誤差 0，128 個原候選的 RelGT 分數不變，新候選與歷史可推論；詳見 `model-validation/3.1.21目錄與模型核對.json`。沒有宣稱準確率改善，沒有新增付費服務。

## 手動快捷與配料背景

手動推薦新增「自訂快捷設定」：最多 8 個，名稱 1～20 字、偏好文字 1～300 字，可新增、刪除、恢復預設。點快捷只填入偏好，保留其他篩選，不自動送出推薦。訪客保存在此瀏覽器；登入者保存到獨立帳號欄位，不與對話快捷互相覆寫。切換帳號清除前一位的顯示，延遲回應不覆蓋新帳號。D1 migration 0009 加入欄位，沿用原登入及內容驗證，不新增服務。

背景芋圓以穩定的配料序號交錯橘黃與紫色，保留圓潤形狀、漸層與微弱投影；混選其他配料時仍有兩色。製杯 loading 同步使用兩色。背景關閉、分頁隱藏、減少動態效果、30fps 上限、閱讀區遮罩及 API 完成後清除 loading 的既有行為保留，配色不影響推薦條件。
