# 3.1.5：①推薦診斷＋③訓練前後比較

依使用者指定，保留原有原話／實際回覆／飲料對照與推薦診斷，新增獨立「③訓練前後成效比較」頁籤，避免長報告把推薦檢查往下推。

## 可以看到什麼

- RelGT、RoBERTa、Qwen 每個執行的開始時間、成功／失敗／略過、實際步數、訓練前／後／差值及指標方向。百分率顯示百分比，差值為百分點。
- 實際失敗與重試分開，不覆寫首次失敗；缺少後測顯示未取得，不補零或補造差值。數值退步、持平及改善分開顯示。
- 權重有無更新與重載最大誤差、基礎版本、候選及資料／目錄／查詢／標籤規則 hash；原報告沒有的欄位為 null／未取得。
- 評估範圍明示：RelGT 訓練內或獨立時間切分抽樣驗證、RoBERTa 目錄代理、Qwen 人工合成意圖。loss 不能代表推薦改善；合成情境不是真實對話。
- 報告的 published 欄位只描述當次訓練記錄；後續是否啟用要另看目前連線版本，不把官方 base 對候選比較冒充正式舊版／候選發布驗證。

目前同步16筆上述三個訓練入口的既有紀錄。MacBERT、舊價格實驗及不同任務的前置檢查不混入此頁。同步既有報告沒有重新訓練或改模型。

## 安全與同步

新增 D1 0005_training_summaries 表及索引，不變更既有用戶／偏好／互動資料。`scripts/build_training_summaries.py` 只擷取固定欄位、固定指標及版本 hash，不上傳原始報告、用戶事件、查詢、訓練例句、錯誤堆疊或權重。

`POST /api/training/reports` 使用既有 SEMANTIC_KEY 的服務驗證；Worker 再驗證欄位白名單、run ID／模型一致、有限數值及差值。`GET /api/internal/training` 仍須團隊 session，未登入401、跨站403。靜態JS沒有訓練資料或金鑰。相同run ID重送維持同一筆，失敗與重試用不同run ID保留。

手動重送安全摘要：

```sh
node scripts/sync_training_reports.mjs
```

每日 `run_daily_training.py` 的各模型報告寫好後會呼叫相同同步入口；最多讀取最近120筆摘要，單筆送出、同步有timeout。同步失敗會寫 dashboard_sync=failed 並使批次以失敗狀態結束，訓練報告與實際步數不會因此消失。防重疊略過時不另行同步。保留每天02:00（Asia/Taipei），沒有改排程；此功能不發布權重。

`--check` 已核對新入口存在；此次未執行每日訓練。新排程整輪同步尚待下一次真實執行；手動摘要產生、重送、API及排程失敗處理已分別驗證。
