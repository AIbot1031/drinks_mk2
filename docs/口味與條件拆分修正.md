# 口味與條件混合句拆分修正

2026-10-14，Asia/Taipei。使用者反映同一句寫口味、咖啡因條件會被歸入口味。本次檢查用人工合成的混合寫法與模型錯誤輸出測試，不宣稱取得使用者未提供的原始句子或真實對話紀錄。

例如「清爽回甘，咖啡因50mg以下，預算80元」應拆成：

| 類別 | 值 | 用途 |
| --- | --- | --- |
| 口味 | 清爽、回甘 | MacBERT／備援文字檢索的排序文字 |
| 咖啡因 | 每杯 ≤ 50 mg | 先排除超過上限、未知或估算資料的杯型 |
| 預算 | 每杯 ≤ 80 元 | 先排除超過預算、未知或估算價格的杯型 |

咖啡因及預算不再留在對話的 `state.query` 或最終搜尋的 `query` 裡。候選仍須通過數值篩選，沒有把它們當成可忽略的相似度偏好。

## 修正內容

- 先從使用者本輪文字辨識數值與有效比較，套用到篩選欄位；支援「咖啡因含量50以下」「咖啡因要在50mg以下」「咖啡因在50以下的清爽茶」，有無逗號均可。
- 「低咖啡因的清爽茶」「低熱量的果香飲料」會保留口味。低咖啡因沿用既有每杯 100 mg 上限政策，低熱量沿用 200 kcal，會顯示採用數值的提示；同一句指定明確上限時採指定值。
- 新增共用 `flavorQuery`，在規則狀態、Qwen 輸出合併、Worker 搜尋入口及推薦引擎，清除數值限制文字。即使 Qwen 又把咖啡因條件寫回 query，也不會送入口味檢索。
- 從模型 query 清除的數字不會反過來修改已驗證的 filters。測試讓模型寫「咖啡因999、預算5」時，仍保留使用者明確指定的咖啡因50、預算80。
- 若模型只回傳數值而漏掉口味，使用本輪規則已辨識的正向口味；不把數值當成新口味。
- 舊頁面 state.query 內殘留的數值會移除；缺少對應篩選時才補已可解析的上限。已有篩選不被舊文字覆蓋，接著提高預算／解除咖啡因不會被舊口味中的數字重新限制。
- 尚未理解的數值片段清理會在已知口味、品牌、配料排除及過敏詞前停止，避免清掉句子後面的其他需求；過敏限制也另從原始本輪文字保留。
- 硬條件先解析，再清除檢索文字。手動查詢的無效數值與過敏限制仍會阻擋推薦，沒有透過清理文字繞過限制。

本次仍使用 Qwen3.5-9B intent-v7，沒有修改提示或權重，沒有訓練，optimizer 步數為 0。這是解析與搜尋契約的修正。

## 驗證

更新前正式站的八個混合句人工情境通過四個：一般逗號、有數值的無逗號、多上限、無效零值保留口味本來正常；「咖啡因含量」「咖啡因要在」「低咖啡因的口味」「咖啡因在…的口味」有解析或口味保留缺口。本次沒有把「所有混合句都失敗」當成事實。

相同八組、相同程式、相同判準的正式站前後實測由 **4／8 改為 8／8**，差值 +4，沒有退步。新版七項一般解析實際使用 Qwen3.5-9B，無效零值由程式追問。前後實測保存在 `docs/口味與條件拆分線上驗證.json`。判準包括上限是否在 filters、口味是否保留、query 是否排除數值描述、是否需要澄清，以及所有回傳杯型是否符合咖啡因／預算。

本機 Worker 的 69 項測試全部通過、0 略過。包含真實 WebSocket 推論協定的合成 Qwen 角色，刻意回傳把口味與數值混在一起的 query，確認網站 state.query 與搜尋 query 都清理成功、已確認上限不變。測試替身不是本機 9B 模型，不以它宣稱模型品質改善。首次替身誤用 `conversation` 協定名稱而非真實的 `chat`，造成 timeout 及一項失敗；修正測試後全數通過，首筆安全摘要保留於 `.wrangler/mixed-intent-20261014/first-test-failure.json`。

此外，重播既有 Qwen 驗證的 21＋8 份輸出至新合併程式，網站契約保持 21／21、8／8；不是重新生成或重新訓練。型別、build、Wrangler dry-run、diff 格式檢查通過。

另外四項正式站檢查通過：原始過敏限制跨輪保留、未支援下限與範圍釐清仍保留配料排除、舊 query 的預算不覆蓋新預算。三模型 connected／ready，目錄版本未變。未建立正式帳號或寫入顧客偏好事件。本機 Worker 已停止，獨立合成帳號與 trace 資料庫已刪除。

## 程式與發布

- `worker/numeric-language.ts`：混合句的數值辨識、低咖啡因／熱量政策提示及 flavorQuery。
- `worker/conversation.ts`：原有狀態修復、口味保留及條件分欄。

## 限制

語句沒有明確上限、含不支援單位／範圍、數值不能成立時，仍會追問；會保留已辨識的口味。清理模型 query 可以阻止條件污染檢索，不能保證所有未知口味都能正確理解。零咖啡因等上限仍依目錄資料篩選，不代表新增成分安全保證。合成契約通過數不是顧客滿意度或真實排序相關性指標。
