# 飲料專案需要的訓練集

2026-10-15，Asia/Taipei。本文件是資料準備建議，沒有啟動訓練、建立新訓練集或替換線上權重。

## 優先準備 Qwen 的意圖對照集

每筆資料要有：案例 ID、前一輪口味與完整條件、本輪輸入、正確 action／query／完整 filters、需要追問的內容、情境分類、來源及人工確認結果。送進訓練時須使用與正式服務一致的提示、欄位及 Worker 預處理結果；目前服務傳入的 state 已套用本輪規則，原始上一輪狀態也應在標註來源中保留，避免混淆兩者。

你可以先用表格標註，再轉為 JSONL：一行一筆，使用 system／user／assistant 的 messages；assistant 放核對過的正確解析。這是現有 MLX-LM 支援的聊天資料格式，[官方資料格式說明](https://github.com/ml-explore/mlx-lm/blob/main/mlx_lm/LORA.md#data)。

案例需包含一般需求、錯字／注音／中英混寫、否定及解除、複選配料、多輪只改一項、數值與單位、含糊及矛盾需求、心情雜訊、離題或要求忽略規則。不要讓每筆都成為奇怪輸入；保留常見簡單需求，避免新能力擠掉原有行為。糖度、冰量、過敏原等資料尚未驗證時，標籤應如實說明限制，不能假定已符合。

目前先以 **300–500 筆人工確認的意圖案例，另留約 100 筆獨立測試** 作下一輪整理工作量，其中安排約 100 筆多輪複合條件。這是本專案的起步建議，不是提升效果的保證或最低門檻。先核對少量標註的一致性，再擴增同義說法；合成案例必須註明來源，不當作真實顧客紀錄，也不直接把待訓練模型的答案當標準答案。

分開 train、validation、test：訓練用來學習，validation 選設定，test 在決定設定後才評估；同一對話、近似改寫或同一生成模板不得跨集合。原 59 題回歸集繼續保留，另增加尚未檢視的新測試集。比較完整條件保留、指定欄位修改、否定／解除、複選與追問正確率；訓練 loss 降低不等於理解或推薦改善。

上一輪實際使用 73 筆合成訓練，完整意圖由 36/59 降至 22/59，候選沒有上線。漏掉舊預算、品牌排除及奶茶否定是已觀察的問題；「多輪資料不足」只是可能原因，沒有證明因果。詳見 [完整報告](training-runs/20261014T222622-qwen-intent-qlora.md)。

## MacBERT 的語意配對集

有用的資料是「需求、適合的飲料／風味文字、容易混淆但不適合的飲料」，例如「想喝花香清爽的茶」配對已標記花香的茶，另選濃郁奶茶作區分。相似度標籤應核對風味和成分，不把未喝過當不喜歡，也不靠品牌重複或價格數字冒充語意。

目前 scripts/train_macbert.py 使用目錄文字做無監督對比訓練，尚未直接接受這種人工配對集。使用額外配對時需擴充讀取與監督訓練，再用保留需求的檢索命中率比較。句對及三元組格式參考 [Sentence Transformers 官方說明](https://sbert.net/docs/sentence_transformer/dataset_overview.html)；這是方法參考，不代表本專案目前使用該套件訓練。

## RelGT 的真實偏好互動集

目前可用的事件需有匿名化 user_code、drink_id、action、occurred_at、事件 ID 與資料目錄版本。action 為喜歡、不喜歡、取消喜歡、取消不喜歡，對應 like／dislike／unlike／undislike。保留同一使用者多次選擇的時間順序，配合飲料目錄的品牌、茶種、奶類與配料關係。

候選或未點選品項不能全部標成真實不喜歡，模擬人物也不能冒充真實互動。每個訓練目標只能看到它發生前的歷史；資料足夠時按時間分 train／validation／test，不能用未來的收藏預測過去。少量有效真實目標仍可執行首次訓練，但沒有獨立保留集時不能宣稱排序已改善。

資料整理只留任務必要資訊；密碼、金鑰、cookie、原始帳號識別或完整顧客互動不放入 GitHub。真正模型效果需用相同獨立資料比較後再決定是否上線。
