# 所有模型的訓練前後比較規範

2026-10-13 使用者要求：不管訓練哪個模型，每次都寫報告，顯示訓練前後差異。此規則已加入 AGENTS.md。

## 每次必須交代

- 執行狀態、起訖時間（Asia/Taipei）、實際 optimizer 步數；成功、失敗、資料不足而略過都記錄。
- 起始模型與完成模型、資料截止時間及 hash、程式版本／dirty 狀態、參數、資料清理、新增數與切分方式。
- 比較相同驗證資料與方法的實測數值：前、後、差值（後−前）與指標方向；未取得寫明原因，不能補估計值。
- 實際權重、保存／重新載入檢查、是否上傳／切換網站、更新用戶數與目前網站方法。
- 這次更新了什麼、理由、限制及下一步；不把下降的訓練 loss 當成消費者推薦變好的證據。

`training/run_reports.py` 為共用比較器；`scripts/train_macbert.py` 與 `scripts/train_preferences.py` 在所有執行結果都產生比較段落與 JSON 欄位。長期意圖尚未有正式 trainer，目前 `scripts/check_long_term_training.py` 只作前置檢查並產生略過報告，不假裝完成模型。

## 任務分開解讀

MacBERT：目前固定驗證文字的 dropout 對比 loss 可作前後對照；這不是查詢相關性、Recall@K 或 NDCG@K。未標註查詢時不能聲稱推薦提升。

RelGT：長期意圖需要同一人的跨時間事件，歷史截止在目標事件之前，採時間切分。現有快照 BCE 入口只有早期偏好分類，不具備長期時間圖，不能替代此目標。

價格：直接取資料庫，已依使用者要求停用價格訓練入口。歷史價格報告的前後驗證 MAE／RMSE 只供追溯，不再執行。

## 目前長期意圖資料收集

已部署 `consumer_interactions`：登入用戶的 like、unlike、dislike、undislike，以伺服器時間記錄飲料 ID、帳號關聯、請求 ID 與目錄版本。偏好與事件在 D1 batch 中一同提交或回滾；用資料庫當下狀態比較，避免重複 PUT 製造事件。取消收藏不直接標成不喜歡。

沒有猜測或回填舊操作時間。測試帳號不計入訓練資料；訪客目前的本機收藏沒有登入身份，不收進個人長期資料。沒有保存新原始查詢文字、密碼或 session 到此事件表。

仍待完成：匿名事件匯出、時間圖／樣本適配、真正的長期意圖訓練入口、同資料前後排序評估、版本發布及排程。單純建立事件表不表示以上已完成。

歷史報告已依原始實測補上比較段落，補記日期為 2026-10-13，沒有重跑歷史訓練，也沒有編造缺失指標。資料不足時比較結果為「未更新權重、未發布、0 位用戶更新」。
