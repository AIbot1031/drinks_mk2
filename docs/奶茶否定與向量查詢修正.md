# 奶茶否定與向量查詢修正

紀錄時間（Asia/Taipei）：2026-10-14T10:02:27+08:00。本次修正程式及提示詞，沒有模型訓練。

## 問題來源

「不喜歡奶茶」仍包含奶茶這個詞，原規則看到奶茶就設 milkTea=true；milkTea=false 又只代表不限定，沒有真的排除。對話／手動 API 還會把原文字或 Qwen 產生的奶茶 query 傳給 MacBERT，因此同時出現向量主題偏向奶茶與硬篩選沒有排除的問題。

## 修正後流程

1. 先解析肯定與否定，不能只看有沒有提到奶茶。milkTea=true 表示要奶茶、false 表示排除、省略表示不限。
2. 排除條件進 filters；query 只保留沒有被否定的正向口味。舊對話若把「不喜歡奶茶」存成正向 query，也會先修復。
3. 僅說不喜歡奶茶而沒有正向口味時，Qwen 不能自行補紅茶／其他口味；Worker 強制先追問，state.query 留空，不送奶茶向量查詢。
4. 說不喜歡奶茶但想喝綠茶，query 就是綠茶，保留 milkTea=false。
5. 先把奶茶候選從合格池移除；A 的 MacBERT／TF-IDF、B 的 RelGT／特徵圖以及最後杯型都只能使用合格池。即使模型給奶茶高分，也不能重新放回。
6. 「奶茶可以了」只解除排除，不等於指定奶茶；「改喝奶茶」才切换為正向需求。預算、品牌及其他排除保留，換批仍不重複。

奶茶分類依名稱（奶茶／奶綠／奶青／奶烏龍）或同時含茶與奶標記；鮮奶茶等也屬此分類。不喜歡奶茶不等於無奶，所以牛奶可可等未含茶的含奶飲料不因這一條件被排除。這是資料分類篩選，不是過敏或成分安全保證。
