# RelGT 本機訓練規劃

## 目前確認的參考

- 官方程式：[snap-stanford/relgt](https://github.com/snap-stanford/relgt)
- 論文：[Relational Graph Transformer，arXiv:2505.10960](https://arxiv.org/abs/2505.10960)
- 此次閱讀的官方程式提交：`19e423ca3e7cac761130aba790857f2dc3a46ef7`

官方模型針對多表格關聯資料，以特徵、節點型別、hop 距離、時間及局部結構組合 token，再結合局部 attention 與全域 centroid attention。它不是將飲料互相連線後就自動完成的推薦模型。

## 本機訓練，Cloudflare 提供網站

建議分成兩部分：

```text
本機：Excel／互動資料 → 建立關聯圖 → 訓練與驗證 RelGT → 匯出版本與飲料向量
Cloudflare：接收需求 → 硬篩選 → 使用匯出向量形成 B 榜單 → A/B 融合 → 顯示結果
```

不需要在每次使用者推薦時重新訓練。訓練完成後的向量、模型版本、訓練資料版本與驗證指標應一起保存；模型或資料更新後，需要重新匯出並部署。

目前連接的訓練目標環境已確認為 Mac mini、Apple M6、32 GB 記憶體。官方 README 的實驗腳本面向 Linux、CUDA 及 8 張 NVIDIA A100 80 GB；官方說明可以依環境調整。因此不能直接把官方 CUDA 安裝指令貼到你的 Mac 執行。之後需驗證 CPU／MPS 路徑、PyTorch Geometric 套件相容性，並縮小 channels、heads、層數、採樣長度與 centroids。

## 需要先建立的訓練資料

目前只有飲料 Excel，沒有完整的跨使用者收藏、點擊、購買及事件時間資料。可先建立飲料、品牌、茶種、奶類與配料的關聯表，但不能把原表分類當成真實消費者偏好。

若目標是學習消費者推薦，需定義互動表、標籤、時間切分與評估指標。若先做飲料圖自監督預訓練，需要另行設計任務與防止標籤資訊洩漏；其結果應稱為飲料表示預訓練，不能宣稱已完成偏好模型或重現論文 benchmark。

現在訪客收藏保存在瀏覽器，登入用戶的收藏保存於帳號。帳號偏好是當前快照，沒有收藏／點擊／購買的完整事件時間序列；推薦 D1 紀錄仍沒有帳號欄位，也不是完整訓練事件表。未經資料設計與授權整理，不能直接把它當協同推薦訓練集。

## 本專案狀態

目前已閱讀官方 README、模型與局部 attention 程式，尚未移植官方 RelGT、安裝訓練環境、執行訓練或匯出訓練向量。網站 B 榜單仍為特徵圖隨機遊走，團隊檢查頁與每筆 trace 會標示方法，避免混淆。

後續正式實作需先完成：任務與標籤定義、資料適配、硬體相容性檢查、小型訓練驗證、向量匯出與 B 榜單接入。路徑 C、Agent C 與 Cloudflare Workers AI 仍不加入。


## 已確認的夜間訓練設定

使用者確認：Mac M6、32 GB，每天凌晨 04:00 開始，訓練到完成。

| 設定 | 決定 |
| --- | --- |
| 執行機器 | Mac mini／Apple M6／32 GB（已以目前連接環境的硬體資訊核對） |
| 時區 | Asia/Taipei（台灣時間） |
| 啟動時間 | 每天 04:00 |
| 結束時間 | 不指定固定截止時間，執行到訓練與驗證完成 |
| 雲端更新 | 只有新版本通過驗證後才切換；失敗時繼續使用舊版本 |
| 重複執行 | 前一次仍在執行時，不啟動第二份訓練 |
| 斷線或重新啟動 | 後續程式需要保存 checkpoint 與資料快照，支援恢復，不發布不完整版本 |

以上是已確認的目標設定，並非已啟用的排程。現階段尚未建立互動事件匯出、Mac RelGT 訓練入口、checkpoint 續訓、模型驗證／發布，以及本機排程。需要先完成可手動執行的小型訓練測試，再依實測記憶體與時間決定模型大小，最後接上每天 04:00 的 macOS 排程。

本機訓練時需保持 Mac 開機且能連網，並安排防睡眠。不能保證睡眠、關機或斷線時準時執行。此訓練流程不使用 Cloudflare Workers AI。
