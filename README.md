# 飲料智慧推薦系統

依照提供的架構圖，逐步建立融合式飲料推薦系統。目前已整理資料與路徑 A 的參考程式，尚未完成整套系統。

## 開發範圍

- 路徑 A：以飲料描述建立向量資料庫，搭配欄位條件進行推薦。已有使用者提供的 Chroma 原型。
- 路徑 B：圖關係推薦，後續實作。
- 使用者需求理解、限制條件、候選融合、排序、推薦解釋、結果驗證與回饋：後續實作。
- 路徑 C（SASRec／BST 序列推薦）：目前不實作。

## 路徑 A 原型執行方式

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python src/route_a.py
```

建議使用 Python 3.11 或 3.12。依賴尚未鎖定版本；以上流程尚未完成實際向量建置與查詢驗證。首次執行可能需要網路下載 Chroma 預設 embedding 模型。

程式會讀取 `data/飲料推薦系統_整理版.xlsx` 的「綜合飲料特徵」工作表，在本機 `chroma_db/` 建立向量資料，並執行程式內預設的查詢範例。每次執行會刪除並重建 `drink_menu_basic` 集合，請勿與正式資料共用。

目前沿用參考程式的 Chroma 預設 embedding；架構圖上的中文 embedding 模型尚未接入，也尚未接入 LLM 或路徑 B。

## 資料概況

目前主表有 1,178 筆具品項名稱的飲料，18 個品牌標籤。咖啡因欄位有 367 筆空白，熱量欄位有 239 筆空白。空白代表未知，不應當成零。

I 至 O 欄的七個過敏原表頭都叫 `allergen_egg`，需核對原始來源才可辨識各欄。原型把後六個重複欄標記成未知過敏原，但第一欄的實際意義也仍待確認。「無」依資料說明僅代表文字未命中，不能據此保證不含過敏原。目前「不要花生、堅果類」的範例只有語意查詢，尚未加入對應的排除條件。

價格中的「起」表示起價；熱量和咖啡因需要依容量、冷熱與甜度確認適用條件。參考程式以 200 kcal 和 100 mg 作為範例篩選門檻，尚非正式推薦規則。
